# Phase 3 Workflows

## 1. Employee registration

`POST /employee` (`employee.create`) → `EmployeeService::create`

1. Placement validated via Identity `AssignmentService::validatePlacement` (branch/department must belong to company).
2. Transaction: employee row created; `employee_number` generated by `EmployeeNumberService` — `EMP-{branch_code}-{seq}` when a branch is placed, else `XERIN-EMP-YYYY-{seq}`. Input-supplied numbers are ignored.
3. Personal details (incl. encrypted `national_id`) saved; `employee.created` audit + event.
4. Initial status: `draft`/`pending_approval`/`onboarding`/`active` (validated set); defaults to `onboarding`.
5. Onboarding checklist can then be started (`POST /employee/{e}/onboarding`).

## 2. Status transition

`POST /employee/{e}/status` → `transitionStatus` in a transaction.

- Requires reason + authorized actor; effective date optional.
- Target-status permission mapping (suspend / terminate / approve / update).
- Writes `audit_logs.employee.status_changed` (old/new + metadata) and a `status_changed` `employee_events` entry visible on the profile's Activity Timeline.
- Employees are never hard-deleted; `resigned`/`terminated` are terminal statuses (soft delete retained for archival).

## 3. Transfer (existing, re-verified)

1. `employee.transfer.request` holder submits `POST /employee/{e}/transfers` (to branch/department/position, effective date, reason).
2. `employee.transfer.approve` holder approves → `TransferService` closes the old `employee_assignments` row, opens the new one, updates `employees` placement, and re-syncs the linked `users` placement (branch-scoped permissions take effect immediately).
3. Rejection leaves the current assignment untouched. Attendance/ticket/audit history stays under the originating branch.

## 4. Offboarding (existing)

Initiate → approve → complete (checklist). Completion sets `separated` and revokes the linked user's access. Full reason/dates/actor audited.

## 5. Documents (existing)

Upload (`employee.document.upload`, MIME+size validated, confidential categories flagged) → download only via `GET /employee/documents/{id}/download` (`employee.document.view`) — never a public URL. Delete requires `employee.document.delete`. All actions audit-logged.
